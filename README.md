# Astra — локальный ИИ-ассистент, который управляет компьютером

Astra — это приложение на Python, которое соединяет **LM Studio** (локальная нейросеть) с вашим
компьютером: ассистент открывает программы, печатает текст, нажимает клавиши и кликает мышью,
ищет и читает файлы, выполняет команды в консоли, делает скриншоты, ищет в интернете.
При запуске Astra спрашивает режим работы — **💬 обычный** (чат с текстом) или
**🎤 голосовой** (квадратное окно с прозрачной 3D-сферой из голубых точек, которая дышит от голоса,
и живым блоком статусов «Открываю блокнот», «Листаю отзывы», «Ввожу текст в поле ввода»).

Всё работает локально: модель живёт в LM Studio на вашем компьютере, переписки хранятся в SQLite.

## Возможности

| Блок | Что умеет |
|---|---|
| **Модели** | Список моделей подтягивается из LM Studio, выбор сохраняется в `data/config.json` и переживает перезапуск |
| **Серверы** | Сначала LM Studio в локальной сети (`10.0.0.5:1234`), если его нет — этот компьютер; переключение на лету без перезапуска |
| **Текст** | Чат с историей, стримингом ответа, markdown, копированием, «озвучить сообщение» |
| **Голос** | Запись с микрофона + автоопределение конца фразы (VAD), локальное распознавание (faster-whisper large-v3), ответ озвучивается: edge-tts, а при недоступности сети — офлайн-голос Windows |
| **Статусы действий** | ИИ сам пишет, что делает («Читаю отзывы», «Нажимаю кнопку поиска»); если забыл — фраза собирается из инструмента и его аргументов |
| **Режимы** | Экран выбора при запуске: 💬 обычный чат или 🎤 голосовой режим. Режим запоминается (или спрашивается каждый раз), переключается кнопкой в шапке |
| **Голосовой режим** | Квадратное окно на чёрном фоне: прозрачная 3D-сфера из голубых точек плавно расширяется и сжимается от голоса, ниже — блок статусов, который заполняет сам ИИ |
| **Сфера** | Canvas-рендер без библиотек: точки по спирали Фибоначчи, 3D-проекция с перспективой, глубина по яркости, мягкое свечение и дышащий радиус |
| **Речь (STT)** | faster-whisper **large-v3** по умолчанию (точная расшифровка русской речи) + смена модели на лету: `large-v3-turbo`, `medium`, `small` |
| **Постоянное слушание** | В голосовом режиме микрофон слушает всё время и выключается ровно на время ответа и выполнения действий |
| **Орб** | Большой круг с вращающимся градиентом, вокруг по орбитам кружат маленькие кружки: они вливаются в центр и вылетают обратно, реагируя на громкость голоса (обычный режим, голосовой ввод) |
| **Окна** | Работа внутри конкретного окна: активировать браузер, кликнуть по элементу страницы, напечатать в поле, снять снимок только этого окна |
| **Зрение** | Модель получает и текст, и снимок окна/экрана (multimodal). После каждого действия снимок прикладывается автоматически; если модель без зрения — авто-откат на текст |
| **Разметка и координаты** | Снимок с координатной сеткой и нумерованными метками элементов (Set-of-Mark): модель кликает по номеру метки, а не угадывает пиксели |
| **Проверка результата** | Сравнение экрана до и после действия: если ничего не изменилось, агент не считает задачу выполненной и пробует другой способ |
| **Динамика** | Ожидание загрузки и появления поп-апов, работа с выпадающими списками, бесконечной прокруткой; на капче агент останавливается и передаёт управление человеку |
| **Сессии** | Полноценная история чатов: поиск, закрепление, переименование, удаление, экспорт в Markdown |
| **Инструменты** | 43 действия над ОС: программы, клавиатура, мышь, окна, зрение, файлы, консоль, звук, питание, веб |
| **Безопасность** | Подтверждение опасных действий (консоль, питание, удаление файлов, ввод текста), «разрешить всегда» для конкретного инструмента |
| **Настройки** | Модель, температура, шаги агента, голос, устройства ввода/вывода, порог тишины, права инструментов |

## Требования

* Windows 10/11 (основная платформа; Linux и macOS тоже запускаются, но с ограничениями ввода)
* Python 3.10+
* [LM Studio](https://lmstudio.ai/) с загруженной instruct-моделью (Qwen2.5-7B-Instruct,
  Llama-3.1-8B-Instruct, Mistral-Nemo и т.п.)
* Микрофон и динамики (для голосового режима)
* Интернет — только для edge-tts (озвучка) и поиска в интернете; распознавание речи полностью локальное

## Установка

```bat
cd astra
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Или просто дважды кликните **`start.bat`** — он сам создаст окружение, установит зависимости и запустит приложение.

### Запуск LM Studio

1. Откройте LM Studio → вкладка **Developer** → **Local Server** → **Start Server** (порт `1234`).
2. Загрузите модель (кнопка выбора модели вверху).
3. Запустите Astra: `python run.py`
4. Откроется браузер на `http://127.0.0.1:8756`.

Первый голосовой ввод скачает модель Whisper **large-v3** (~3 ГБ) — это разовая операция,
зато расшифровка русской речи заметно точнее. Если компьютер слабый, модель можно сменить
(«Настройки → Голос → Модель распознавания речи» или список под сферой) на `large-v3-turbo` или `medium`.

### Где искать LM Studio: локальная сеть или этот компьютер

Astra сама решает, к какому серверу подключиться. По умолчанию список адресов такой:

1. `http://10.0.0.5:1234/v1` — LM Studio на другом компьютере в локальной сети;
2. `http://127.0.0.1:1234/v1` — LM Studio на этом же компьютере.

Проверка идёт по порядку, берётся **первый ответивший** сервер:

* если доступен `10.0.0.5` — работаем с ним (быстрее и мощнее, если там сильная видеокарта);
* если нет — автоматически переключаемся на локальный, без ошибок и перезапуска;
* если сервер пропал **посреди работы** — текущий запрос повторяется на резервном адресе;
  фоновая проверка раз в 20 секунд уведомляет интерфейс и показывает всплывающее сообщение;
* если модель, выбранная ранее, на новом сервере отсутствует — подставляется первая доступная.

Вверху справа рядом с моделью есть индикатор сервера (зелёная точка + адрес). Клик по нему
открывает настройки, где можно:

* увидеть список адресов с задержкой и количеством моделей у каждого;
* добавить свой адрес (например, `10.0.0.5:1234` — схему и `/v1` можно не писать);
* нажать «Проверить серверы», чтобы обновить статусы;
* выключить автовыбор и закрепить один конкретный адрес.

Чтобы LM Studio был доступен по сети, на том компьютере включите
**Developer → Local Server → Serve on Local Network** (и разрешите порт 1234 в брандмауэре).

Адрес можно задать и при запуске:

```bat
python run.py --lm-url 10.0.0.5:1234
```

## Режимы работы: обычный и голосовой

При запуске (`python run.py`) открывается экран выбора:

* 💬 **Обычный** — привычный чат: история слева, шаги агента, настройки.
* 🎤 **Голосовой** — отдельный экран в квадратном окне на чёрном фоне.

Если поставить галочку «не спрашивать при следующем запуске», Astra запомнит выбор — вернуть
вопрос можно в «Настройки → Голос → Режим при запуске». Режим также задаётся флагами
`python run.py --mode voice` и `python run.py --mode text`, а переключается кнопкой 🎤 в шапке чата.

### Голосовой режим

```
        ╭──────────────────────────╮
        │   сфера из голубых точек │  ← дышит от голоса: плавно расширяется и сжимается
        │         ·  ·  ·  ·       │
        ╰──────────────────────────╯
        ЧТО ДЕЛАЕТ ASTRA
        ▸ Открываю блокнот          ← этот блок заполняет ИИ по ходу работы
        ✓ Листаю отзывы
        ✓ Ввожу текст в поле ввода
        [🎤]  слушаю — говори
```

1. **Сфера** — прозрачный шар из ~780 голубых точек (`astra/static/sphere.js`, чистый Canvas 2D,
   без библиотек). Точки распределены по спирали Фибоначчи, вращаются в 3D и проецируются
   с перспективой; ближние ярче, дальние тусклее. Громкость голоса плавно увеличивает радиус,
   ускоряет вращение и «раздувает» точки. В ответе ассистента сфера пульсирует в такт речи.
2. **Микрофон слушает постоянно.** Как только вы замолчали (пауза `voice.silence_ms`), фраза уходит
   в распознавание. На время ответа и выполнения действий прослушивание **выключается**, а после
   ответа (и после озвучки) включается снова — ничего нажимать не нужно.
3. **Блок статусов** заполняет модель: в плане каждого действия есть поле `status`, и Astra
   показывает именно его («Открываю блокнот», «Читаю отзывы»). Если модель поле не прислала,
   фраза собирается автоматически из инструмента и аргументов (`astra/status.py`, 40+ шаблонов).
   Выполненные пункты помечаются ✓, текущий — ▸, ошибка — ✕.
4. **Расшифровка разговора** — последние реплики («Ты: …», «Астра: …») видны под статусами.
5. **Смена модели распознавания** — список прямо над сферой (и в настройках): выберите модель,
   она скачается и загрузится в фоне, статус виден в блоке статусов.
6. Если микрофона нет (или `sounddevice` не установлен), голосовой экран не ломается:
   появляется поле для текста, а статусы продолжают работать.

**Квадратное окно.** В браузере окно не перехватить, поэтому для настоящего квадрата запускайте
`python run.py --mode voice --window` (нужен `pip install pywebview`): приложение откроет окно
760×760 и будет менять его размер при переключении режима.

### Модель распознавания речи

По умолчанию используется **large-v3** — самая точная модель Whisper. Маленькие (`small`, `base`,
`tiny`) заметно быстрее, но часто путают слова, поэтому по умолчанию они больше не ставятся.

| Модель | Размер | Когда выбирать |
|---|---|---|
| `large-v3` ★ | ~3.1 ГБ | по умолчанию: минимум ошибок в русской речи |
| `large-v3-turbo` | ~1.6 ГБ | почти та же точность, но быстрее на слабом CPU |
| `distil-large-v3` | ~1.5 ГБ | компромисс скорость/точность |
| `medium` | ~1.5 ГБ | средний вариант |
| `small`, `base`, `tiny` | 460/140/75 МБ | только если очень слабый компьютер |

Модель меняется в трёх местах и сразу применяется без перезапуска:

* список **над сферой** в голосовом режиме;
* «Настройки → Голос → Модель распознавания речи» + кнопка «⟳ Скачать и применить модель»
  (виден прогресс и статус);
* API: `GET /api/stt/models`, `POST /api/stt/model {"model": "large-v3"}`.

Для точности также включены `beam_size=5` и подсказка распознавателю (`voice.whisper_initial_prompt`),
что это команды ИИ-ассистенту на русском. На CPU large-v3 расшифровывает 5–10 секунд речи за
несколько секунд; на CUDA-сборке `ctranslate2` — почти мгновенно
(`voice.whisper_device = "cuda"`).

### Распознавание на видеокарте: CUDA 12, а не 13

Движок распознавания (`ctranslate2` внутри `faster-whisper`) собран **под CUDA 12** и при первом
вычислении загружает `cublas64_12.dll` (Linux: `libcublas.so.12`). Если в системе стоит только
**CUDA 13**, там лежит `cublas64_13.dll` — это другая библиотека, подменить её нельзя
(major-версии CUDA не совместимы по ABI). Именно отсюда ошибка
`Library cublas64_12.dll is not found or cannot be loaded`.

Что делает Astra:

1. **Не падает.** Понимает, что дело в CUDA, и повторяет распознавание на процессоре.
   В интерфейсе появляется понятное уведомление, а в консоли — строка
   `[stt] CUDA отключена до перезапуска: …`. Дальше всё работает, просто медленнее.
2. **Сама ищет CUDA 12.** При запуске просматривает `site-packages/nvidia/cublas/bin`,
   `…/cudnn/bin`, `…/cuda_runtime/bin`, `CUDA_PATH` и `C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\12.x\bin`,
   прописывает найденные каталоги в `PATH` и предзагружает DLL по полному пути.
   Поэтому достаточно `pip install nvidia-cublas-cu12 nvidia-cudnn-cu12` — **CUDA 13 при этом
   остаётся на месте и не мешает**: 12-е библиотеки живут внутри Python-окружения.
3. **Ставит библиотеки одной кнопкой.** «Настройки → Голос → ⬇ Установить CUDA 12
   (cuBLAS + cuDNN)» — это `pip install nvidia-cublas-cu12 nvidia-cudnn-cu12` (~1 ГБ), после
   установки модель перезагружается уже на видеокарте. Рядом кнопка «🔍 Проверить видеокарту».
4. **Даёт выбрать устройство.** «Устройство распознавания»: `авто` (GPU, если реально работает,
   иначе CPU), `процессор`, `видеокарта`. Ошибка GPU никогда не роняет приложение — только откат.

Варианты вручную, если хочется управлять самому:

```powershell
# 1) проще всего: только библиотеки, без установки CUDA Toolkit
pip install nvidia-cublas-cu12 nvidia-cudnn-cu12
# Astra подключит их сама; либо пропишите вручную:
$env:PATH = "$(python -c "import nvidia.cublas, os; print(os.path.dirname(nvidia.cublas.__path__[0]))")\cublas\bin;$env:PATH"
```

```powershell
# 2) через CUDA 12-совместимый драйвер: у NVIDIA драйвер R580+ держит и CUDA 12, и CUDA 13,
#    поэтому Toolkit 13 можно не трогать — движку нужны только библиотеки, а не сам toolkit
```

```powershell
# 3) экзотика: неофициальная сборка ctranslate2 под CUDA 13 (preview, только Windows)
pip install --force-reinstall --no-deps <cuda13-preview-2.whl>
```

Третий путь — неофициальная сборка (CTranslate2-Reborn, preview), официальной поддержки CUDA 13
в `ctranslate2` пока нет. Для стабильности лучше первый: CUDA 12-библиотеки рядом с CUDA 13.

API диагностики: `GET /api/stt/cuda` (что найдено, что мешает, готовая команда установки),
`POST /api/stt/cuda/recheck`, `POST /api/stt/cuda/install`.

## Как пользоваться

**Текст.** Пишите в поле ввода, `Enter` — отправить, `Shift+Enter` — новая строка.

**Голос.** Кнопка микрофона или `Ctrl+Space`. Говорите — запись остановится сама после паузы
(настраивается) и текст сразу уйдёт в работу. `Esc` — отмена.
Ответ читается вслух, орб при этом пульсирует в такт речи.

**Выбор модели.** Выпадающий список в правом верхнем углу или «Настройки → Модель».
Выбор сохраняется навсегда, пока вы его не измените.

**Чаты.** Слева — история. Кнопка `⋮` у чата: переименовать, закрепить, экспорт, удалить.
Поиск ищет и по названиям, и по содержимому сообщений.

**Шаги агента.** Пока агент работает, его действия видны списком карточек. Как только начинается
финальный ответ, блок сам сворачивается в строку вида «Шаги агента · 3 шага · все успешно» —
ответ читается без лишнего шума. Нажмите на эту строку, чтобы раскрыть шаги обратно
(в истории чата шаги тоже свёрнуты; строка подсвечивается зелёным при успехе, красным при ошибке).

### Горячие клавиши

| Клавиши | Действие |
|---|---|
| `Ctrl+Space` | старт/стоп голосовой записи |
| `Ctrl+Shift+N` | новый чат |
| `Enter` / `Shift+Enter` | отправить / перенос строки |
| `Esc` | отменить запись, остановить ассистента или закрыть окно |
| `Enter` / `Esc` в диалоге подтверждения | разрешить / отклонить действие |
| двойной клик по названию чата | переименовать чат |

## Работа в открытом окне (браузер, любая программа)

Ассистент умеет действовать не «куда-то в систему», а **внутри выбранного окна** — это надёжнее,
потому что окно активируется, а координаты считаются от его содержимого, а не от экрана.

Порядок, который использует модель:

1. `list_windows` — что вообще открыто (заголовок, программа, размер, свёрнуто ли);
2. `focus_window` — активировать нужное окно; в ответ приходят его размеры и точка начала
   области содержимого;
3. `click_in_window` / `type_in_window` / `hotkey_in_window` / `scroll_in_window` —
   действия внутри окна с координатами относительно его левого верхнего угла;
4. `screenshot_window` — снимок только этого окна, чтобы «посмотреть», что на странице;
5. `open_in_browser` — открыть адрес в уже запущенном браузере (активирует окно, `Ctrl+L`, вводит адрес).

Примеры:

* «Открой в Chrome погоду в Мурманске и скажи, сколько градусов»
* «Найди на сайте YouTube видео про Python — кликни в поиск и введи запрос»
* «Переключись в окно Word и напечатай заголовок "Отчёт"»
* «Сверни все окна браузера» / «Разверни окно проводника»

Технические детали (Windows):

* активация окна обходит блокировку `SetForegroundWindow` (AttachThreadInput + трюк с Alt),
  свёрнутое окно предварительно разворачивается;
* снимок окна делается через `PrintWindow`, поэтому он получается даже если окно перекрыто
  другим — но некоторые игры и приложения с аппаратным ускорением отдают чёрный кадр,
  в этом случае автоматически используется снимок по границам окна;
* координаты кликов — от левого верхнего угла **области содержимого** (без заголовка и рамки),
  точка начала отдаётся в ответе `focus_window`.

## Зрение: агент видит окно, а не только текст

Агент получает результаты инструментов **и текстом, и картинкой**. Работает так:

1. Любой инструмент, возвращающий снимок (`screenshot_window`, `take_screenshot`), отдаёт `artifact`
   с изображением — оно уходит и в интерфейс (превью в карточке), и модели.
2. После каждого действия внутри окна (`focus_window`, `click_in_window`, `type_in_window`,
   `hotkey_in_window`, `scroll_in_window`) агент **сам** снимает это окно и прикладывает снимок
   к следующему запросу — так он видит результат своих кликов.
3. Изображение отправляется в формате OpenAI `image_url` с data-URI (JPEG, сжатие до 1024 px,
   максимум 2 снимка на запрос) — LM Studio понимает этот формат для VL-моделей.
4. Режим `auto`: если сервер ответил, что модель не принимает изображения, Astra один раз
   повторяет запрос без картинок, показывает предупреждение и дальше работает по тексту.
   Проверить заранее можно кнопкой **Настройки → Модель → «Проверить зрение»**.

Что нужно: **vision-модель** в LM Studio — Qwen2.5-VL, Gemma 3 (4B+), LLaVA, MiniCPM-V, Pixtral.
Обычные текстовые модели (Qwen2.5-Instruct, Llama-3.1, Mistral) картинки игнорируют — для них
режим `auto` автоматически останется текстовым, и это нормально: остальные функции работают.

Настройки (`data/config.json`, раздел `lmstudio`):

| Параметр | Смысл |
|---|---|
| `vision` | `auto` (по умолчанию) / `on` / `off` |
| `vision_max_px` | до какого размера сжимать снимок (1024) |
| `vision_quality` | качество JPEG (80) |
| `vision_max_images` | сколько снимков максимум в одном запросе (2) |
| `agent.auto_window_screenshot` | автоматически снимать окно после действий (true) |

Индикатор внизу окна показывает состояние: `зрение: 👁 вкл` / `зрение: нет (текст)` / `зрение: авто`.
В карточке действия появляется пометка «снимок передан модели».

## Продвинутое зрение: сетка, метки и проверка результата

Обычного «показать модели скриншот» мало: модель видит картинку, но координаты клика
угадывает и часто промахивается, а после клика не понимает, сработало ли действие.
Поэтому в Astra есть три слоя поверх зрения.

### 1. Координатная сетка (OS-World alignment)

Инструмент **`see_window(title)`** отдаёт снимок окна с нарисованной сеткой и подписями по краям.
Подписи — это **та же система координат, что у `click_in_window`** (от левого верхнего угла
содержимого окна), поэтому модели не нужно пересчитывать масштаб: прочитала «420» с картинки —
передала `click_in_window(title, 420, 300)`.

Шаг сетки настраивается (`Настройки → Модель → Шаг координатной сетки`, по умолчанию 100 px,
`0` — подбирать автоматически под размер окна: 50 px для 800×600, 100 px для 1920×1080).

### 2. Set-of-Mark: элементы превращаются в номера

На том же снимке Astra рисует цветные рамки с номерами на найденных элементах интерфейса —
кнопках, полях, ссылках, строках, иконках. В тексте рядом с картинкой приходит таблица:

```
#17: клик (368, 313), размер 174×40
#18: клик (568, 313), размер 208×40
```

Модель просто пишет `click_window_mark(title, mark=17)` — координаты уже пересчитаны,
промахнуться невозможно. Если нужного элемента среди меток нет, остаётся сетка: координаты
берутся с линий.

Как это работает без тяжёлых моделей: классическое компьютерное зрение на numpy + Pillow —
градиенты → дилатация → связные компоненты → фильтрация по площади и форме (никаких SAM/OpenCV
и никаких лишних зависимостей). На реальной странице с 30 элементами метки находятся за ~40 мс
и попадают точно в кнопки и поля.

Метки нумеруются в порядке чтения (сверху вниз, слева направо) и **пересчитываются при каждом
`see_window`** — после прокрутки или перехода по ссылке разметку нужно получить заново.

### 3. Проверка результата (Visual Verification)

Перед действием в окне агент снимает снимок «до», после — «после», и сравнивает их:

| Вердикт | Что значит | Что делает агент |
|---|---|---|
| `same` | различие меньше 0.02 % и ни один блок 16×16 не изменился | пишет в карточку «⚠ экран НЕ изменился, возможно действие не сработало» и пробует другой способ |
| `micro` | изменилось несколько блоков (подсветка, строка «Сохранено», курсор) | считает, что интерфейс отреагировал |
| `small` | до 3 % пикселей — появилось сообщение, обновился элемент | успех |
| `changed` | больше 3 % — переход, поп-ап, новая страница | успех |

Сравнение идёт по уменьшенной копии 512 px с блочным анализом: тонкая строка текста
(«Проект сохранён ✓») ловится, а мигающий курсор и антиалиасинг шумом не считаются.
Отключить можно в `Настройки → Модель → «Проверять результат по снимку»`
(или `agent.visual_verify = false`), порог чувствительности — `agent.verify_min_diff`.

### 4. Динамические элементы

| Инструмент | Для чего |
|---|---|
| `wait_for_change(title, timeout)` | ждать реакции на клик: смена состояния, загрузка, появление поп-апа |
| `wait_until_stable(title)` | ждать, пока экран перестанет меняться — «загрузка закончилась» |
| `wait_for_new_window(title)` | ждать новое окно/диалог и получить его заголовок |
| `scroll_until_end(title, amount)` | листать, пока содержимое не перестанет меняться (конец ленты, бесконечный скролл) |
| `detect_captcha()` | проверить, нет ли проверки «ты человек» |

Выпадающие списки: клик по полю (метка из `see_window` или Enter/Alt+↓) → `wait_for_change` →
новый `see_window`, где пункты списка уже размечены как метки. Поп-апы и cookie-баннеры —
`wait_for_new_window` + метки на кнопках, закрыть можно `hotkey_in_window(["esc"])`.
Для поиска конкретного текста на длинной странице быстрее Ctrl+F, чем бесконечная прокрутка.

### Капча — только человек

Капчу, reCAPTCHA, «подтвердите, что вы не робот», проверку Cloudflare **решает только человек**.
Astra распознаёт такие окна (по заголовкам: `reCAPTCHA`, `Cloudflare`, «не робот», «капч»…),
показывает предупреждение и **останавливается** — обходить проверки она не пытается.
Отключается в `Настройки → Модель → «Останавливаться на капче»` (`agent.stop_on_captcha`).

### Что нужно от модели

Разметка и проверка работают с любой моделью — это локальные вычисления. Но чтобы модель
*использовала* картинку, нужна vision-модель.
Без зрения агент тоже живёт: `see_window` возвращает таблицу меток текстом, и модель может
кликать по номерам, вообще не видя изображения.

## Озвучка ответов (и что делать, если голоса нет)

Голос звучит на **этом же компьютере** (в колонках/наушниках), а не в браузере: сервер
синтезирует речь и сразу воспроизводит её. Отвечает голосом только на голосовой ввод;
чтобы озвучивались и текстовые ответы — включите «Озвучивать и текстовые ответы».

Движки озвучки идут цепочкой, переключение автоматическое:

| Движок | Что это | Нужен интернет |
|---|---|---|
| `edge-tts` | нейроголоса Microsoft (Дмитрий, Светлана, Дария…) | да |
| `sapi` | **офлайн-голос Windows** через `System.Speech` (PowerShell → WAV) | нет |
| `pyttsx3` | офлайн-резерв, если установлен (`pip install pyttsx3`) | нет |

Внутри офлайн-движка тоже есть резерв: сначала Windows синтезирует WAV, а Astra проигрывает его
через sounddevice (так работает анимация кружка). Если аудиоустройство недоступно Python-слою
(PortAudio не видит колонки), Astra просит Windows произнести текст **напрямую** — звук идёт
через системный стек, и ответ всё равно звучит.

Настройка `voice.tts_engine`:

* `auto` (по умолчанию) — сначала `edge-tts`, при любой ошибке (нет интернета, сервис
  ограничил запросы, «No audio was received») **сразу** офлайн-голос Windows;
* `sapi` — сразу офлайн, без ожидания сети (быстрее всего и работает без интернета);
* `pyttsx3` — если предпочитаете его;
* `edge-tts` — только онлайн.

Если сработал офлайн-резерв, в интерфейсе появляется уведомление
«Онлайн-голос недоступен — озвучил офлайн: офлайн-голос Windows (SAPI)», а индикатор
внизу показывает движок: `голос: edge` / `голос: офлайн` / `голос: ошибка`
(на него можно нажать — откроются настройки голоса).

### Проверка озвучки

**Настройки → Голос → «Проверить озвучку»**. Кнопка синтезирует фразу
«Привет! Проверка голоса Астра. Раз, два, три.» и честно пишет результат:

* `✓ озвучено: edge-tts · ru-RU-DmitryNeural` — работает онлайн-голос;
* `✓ озвучено: офлайн-голос Windows (SAPI) (edge-tts недоступен)` — сработал офлайн-резерв;
* `✕ <причина>` — точная причина: нет движков, нет доступа к устройству вывода, сеть и т. д.

Рядом со списком движков видно, что найдено на этом компьютере: `✓ edge-tts ✓ офлайн Windows — pyttsx3`.
То же самое отдаёт API: `GET /api/tts/status` и `POST /api/tts/test`.

### Если голоса всё равно нет

1. **Проверьте тумблер** «Озвучивать ответы» (и значок динамика в шапке — он должен быть включён).
2. **Проверить озвучку** — кнопка покажет причину, а не просто промолчит.
3. Ошибка «устройство вывода» — колонки/наушники не выбраны или заняты другим приложением;
   выберите устройство в «Настройки → Голос» или в Параметрах Windows.
4. Онлайн-голос не работает без интернета и иногда блокируется сервисом Microsoft
   (ответ «No audio was received») — это нормально: `auto` тут же переключится на офлайн-голос.
5. Офлайн-голос не найден — в Windows не установлен ни один голос. Включите:
   **Параметры → Время и язык → Речь → Добавить голоса** (для русского: «Русский»).
   Свой голос можно указать в `voice.sapi_voice` (например `Microsoft Irina Desktop`);
   пустое значение — системный голос по умолчанию.
6. Озвучка идёт медленно на длинных ответах — первый запуск офлайн-движка дольше
   (PowerShell стартует ~1 с), дальше одинаковые фразы берутся из кэша WAV в `data/tts_cache`.

Похожие ошибки слышно и видно по индикатору: `голос: ошибка` — наведите курсор, в подсказке
будет текст ошибки, клик открывает настройки.

## Как это работает

```
микрофон ──► VAD ──► faster-whisper ──► текст ─┐
                                               ├──► агент (2 фазы) ──► LM Studio
текстовый ввод ────────────────────────────────┘         │
                                                         ▼
                              планировщик: {"tool": "...", "args": {...}}
                                                         │
                              выполнение инструментов (с подтверждением)
                                                         │
                              финальный ответ (стриминг) ──► чат + edge-tts
```

Агент работает в два шага: сначала «планировщик» возвращает строгий JSON с инструментами,
затем отдельный вызов формулирует человеческий ответ по результатам. Это гораздо надёжнее
для локальных моделей, чем попытка получить и действия, и текст в одном ответе.

## Частые проблемы

**«LM Studio не отвечает»** — запущен ли Local Server на одном из адресов из списка кандидатов.
Кнопка ↻ рядом с выбором модели перепроверяет все адреса и показывает, какой из них жив.
Если сетевой сервер включается не всегда, автовыбор сам вернётся на локальный.

**Сетевой сервер есть, но Astra его не видит** — проверьте, что LM Studio на том компьютере
включён режим «Serve on Local Network», порт 1234 не блокирует брандмауэр, и адрес доступен
в браузере: откройте `http://10.0.0.5:1234/v1/models` — должен прийти JSON со списком моделей.

**Модель не вызывает инструменты** — возьмите instruct-модель от 7B, понизьте температуру до 0.15–0.25,
увеличьте `agent.max_steps`. Слишком маленькие модели (1–3B) часто ломают JSON.

**Текст в блокноте идёт одной строкой** — обновлено: переводы строк теперь отправляются
нажатием Enter, а не символом `\n`. Если вы обновлялись со старой версии, просто перезапустите
приложение.

**Модель не видит скриншоты** — загружена текстовая модель. Нажмите «Проверить зрение» в настройках:
если ответ «модель не принимает изображения», загрузите VL-модель. Режим `auto` в этом случае
не мешает работе — агент использует текст (заголовки окон, содержимое страниц, геометрию окна).

**Ассистент не находит окно** — назовите его иначе: часть заголовка или имя программы
(`chrome`, `яндекс`, `word`, `документ.docx`). Список с точными заголовками даёт инструмент
`list_windows` («Что сейчас открыто?»).

**Агент говорит «экран не изменился»** — это и есть проверка результата: клик ушёл, но интерфейс
не отреагировал (элемент переехал, окно перекрыто, кнопка была неактивна). Агент повторит попытку
другим способом. Если проверка мешает (например, страница всё время анимирована), отключите
`Настройки → Модель → «Проверять результат по снимку»` или поднимите порог `agent.verify_min_diff`.

**Кликает мимо кнопки** — пусть сначала вызывает `see_window`: на снимке появятся номера меток,
и клик по `click_window_mark(title, mark=N)` попадает точно. Если метки нет — координаты берутся
с координатной сетки.

**Появилась капча** — пройдите её сами: агент специально останавливается и не пытается обходить
проверки. После прохождения проверки скажите «продолжай».

**Клик в окне попадает не туда** — окно могли перекрыть или изменить размер между шагами;
ассистент перепроверит геометрию при следующем `focus_window`. Если приложение рисует интерфейс
с масштабированием (DPI 125–150 %), координаты всё равно считаются в физических пикселях, поэтому
надёжнее просить «нажми кнопку» через горячие клавиши или `screenshot_window` + уточнение.

**Ошибка `Library cublas64_12.dll is not found or cannot be loaded`** — видеокарта есть,
а библиотек CUDA 12 нет (частая ситуация, когда установлена CUDA 13: у неё `cublas64_13.dll`,
и она не подходит — major-версии CUDA несовместимы). Astra уже переключилась на процессор
и работает; чтобы вернуть GPU, нажмите «Настройки → Голос → ⬇ Установить CUDA 12»
(или `pip install nvidia-cublas-cu12 nvidia-cudnn-cu12`) и «🔍 Проверить видеокарту».
CUDA 13 при этом можно оставить — библиотеки 12-й версии живут внутри Python-окружения.

**Распознавание путает слова** — проверьте модель: должна стоять `large-v3`
(«Настройки → Голос» или список над сферой). Маленькие модели (`small`, `base`, `tiny`)
быстро печатают, но часто переставляют слова; `large-v3` решает именно эту проблему.
Если не хватает скорости — `large-v3-turbo`: точность почти та же, работает быстрее.

**Первая голосовая фраза долго не распознаётся** — скачивается модель Whisper (~3 ГБ для `large-v3`).
Прогресс виден в консоли сервера, а в интерфейсе — статус «Загружаю модель распознавания».
После первой загрузки модель кэшируется в `%USERPROFILE%\.cache\huggingface`, дальше загрузка
занимает несколько секунд.

**Голосовой режим открылся не квадратным** — браузер не позволяет менять размер своего окна.
Запустите `python run.py --mode voice --window` (нужен `pip install pywebview`): откроется
нативное окно 760×760, и при переключении режима оно само изменит размер.

**Ассистент слышит сам себя** — в голосовом режиме прослушивание выключается на время ответа
и озвучки, а одинаковая фраза, распознанная дважды подряд (шум, эхо колонок), повторно
не отправляется. Если эхо всё же мешает, наденьте наушники или увеличьте `voice.silence_ms`.

**Не работает микрофон** — проверьте, что `pip install sounddevice` прошёл успешно, и выберите
устройство ввода в настройках. В Windows разрешите доступ к микрофону для классических приложений.

**Нет звука в ответах** — откройте «Настройки → Голос → Проверить озвучку»: кнопка назовёт причину
(нет движка, нет устройства вывода, сеть) и покажет, каким движком удалось озвучить. Без интернета
`auto` переключается на офлайн-голос Windows (SAPI) — он работает всегда, если в Windows установлен
хотя бы один голос. Полный разбор — в разделе «Озвучка ответов».

**Распознавание медленное** — используйте модель `base` или `small`, для GPU поставьте
`voice.whisper_device = "cuda"` (нужна CUDA-сборка ctranslate2).

## Безопасность

* Сервер слушает только `127.0.0.1` — снаружи недоступен.
* Разрушительные команды (`format`, `rm -rf /`, `vssadmin delete shadows`, …) заблокированы на уровне кода.
* Опасные действия по умолчанию требуют явного подтверждения в интерфейсе.
* Никакие данные не уходят в облако, кроме текста озвучки (edge-tts) и поисковых запросов.
